# Requirements Lens

Use this lens for product requirements, PRDs, feature requests, acceptance criteria, and behavior specs.

Find missing decisions in:

- User goal and success signal
- Included and excluded personas
- Trigger, entry point, and completion condition
- Required, optional, invalid, duplicate, and stale inputs
- Permissions, visibility, and ownership
- Empty, loading, partial success, error, retry, and cancellation states
- Acceptance criteria and pass/fail examples
- Explicit non-goals for this version

Good questions:

- When the input is empty, invalid, duplicated, or stale, should the system block, warn, auto-fix, or accept it?
- Which user role owns the final decision when the system and user disagree?
- What exact behavior proves this requirement is done?
